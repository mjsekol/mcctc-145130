# Six drafted tasks
## Lab M06-01, part 1

Six tasks written for a note-sorting program. **Four of them are broken.** For each
one, write down whether it is usable and, if not, which of the five named problems
it has.

**The five named problems:**

```
A  names a control, a file, a flag, or a menu item
B  asks for an opinion instead of an action
C  asks for something the program cannot do
D  contains its own answer, or contains a finding
E  has no reason a person would actually have
```

A task can have more than one.

---

## The program these were written for

`notesort` reads a folder of short text notes and writes a digest file. The digest
groups notes into five categories and shows a count per category. It has one flag,
`--folder`, which points at the folder of notes. It prints a usage line when it is
run with no arguments.

**It does not** detect duplicates, search for text, filter by day, or let anybody
change a category after the fact.

**Read that paragraph twice before you judge the tasks.** One of the six asks for
something in the "does not" list, and it reads perfectly reasonably.

---

## The six tasks

```
1  Click Run and then read the summary at the top of digest.md.

2  You want to know which of these notes are about somebody being locked
   out of their account. Show me how you would find that out.

3  Try the program out and see what you think of the categories.

4  Find out which notes came in more than once this week.

5  Your printer note got put in the wrong category. Fix it.

6  It is Monday morning and you have fifteen notes and twenty minutes.
   Decide which three you would deal with first, using whatever the
   program gives you.
```
