# Contingency Plan

## What can go wrong

The model may be unavailable, the service may crash, the network may fail, or a
team member may be absent. Any of these will slow the project down and some of
them will stop it completely until somebody fixes the cause.

## What you do about each one

If the model is unavailable, wait for it to come back or install a different
one. If the service crashes, restart it and check the logs. If the network
fails, contact the network administrator. If a member is absent, the other
member covers their work until they return.

## What you cut first

Features that are not essential are cut first, followed by any remaining
optional work, until the project fits the time that is left in the schedule.
